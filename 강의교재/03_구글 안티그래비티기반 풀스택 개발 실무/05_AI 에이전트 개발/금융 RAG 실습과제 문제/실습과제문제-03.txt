[실습과제] 웹 문서(한국은행 연차보고서) 기반 Q&A RAG 구현

권장 파일명: RAG_파이프라인_설계와_구현_웹문서_한국은행_연차보고서_QA.ipynb


────────────────────────────────────────
1. 제공 자료
────────────────────────────────────────

데이터 소스 (웹 페이지)
  - 한국은행 2025년도 연차보고서 게시판 상세 페이지
  - URL:
    https://www.bok.or.kr/portal/bbs/P0000596/view.do?nttId=10097176&searchCnd=1&searchKwd=&depth2=200699&depth3=200071&date=&sdate=&edate=&sort=1&pageUnit=10&depth=200071&pageIndex=1&programType=newsData&menuNo=200071&oldMenuNo=200066

※ PDF 파일이 아니라 웹 HTML 본문 텍스트를 인덱싱에 사용한다.
※ 페이지 구조·본문 위치가 변경되면 파싱 셀렉터를 조정해야 할 수 있다.


────────────────────────────────────────
2. 과제 목표
────────────────────────────────────────

한국은행 연차보고서 웹 페이지를 대상으로
로딩(HTML 파싱) → 청킹 → 임베딩 → Vector DB 저장 → 검색 → 생성까지
완전한 RAG Q&A 파이프라인을 구현한다.

학습 포인트
  1) RAG 전체 아키텍처(인덱싱 파이프라인 / 질의 파이프라인)를 이해한다.
  2) 웹 문서 RAG에서 내비게이션·스크립트 잡음을 제거하고 본문만 추출하는 방법을 익힌다.
  3) HTML 헤딩(`h2`~`h5`) 구조를 활용한 계층적 Chunking을 PDF 실습과 비교·이해한다.
  4) Vector DB(Chroma / Pinecone / Weaviate) 선택 기준을 정리하고, 본 실습에서는 Chroma를 사용한다.
  5) Retriever(Similarity / MMR / MultiQuery)를 비교하고 grounded Q&A 체인을 구성한다.


────────────────────────────────────────
3. 과제 내용
────────────────────────────────────────

[1] 이론 정리 (노트북 Markdown으로 작성)

  다음 내용을 표 또는 요약으로 정리한다.

  (1) RAG 전체 아키텍처
      - 인덱싱: Loading(웹 로더·HTML 파싱) → Chunking → Embedding → Vector DB
      - 질의: Embedding → Retrieval → Generation

  (2) Chunking 전략 비교
      - 고정(Fixed) / 시맨틱(Semantic) / 계층적(Hierarchical)
      - 웹 문서에서는 HTML 헤딩 = 목차인 경우가 많다는 점을 포함한다.

  (3) Vector DB 선택 기준
      - Chroma / Pinecone / Weaviate

  (4) Retriever 종류 및 성능 특성
      - Similarity / MMR / MultiQuery / Contextual Compression


[2] 환경 설정

  - Gemini API Key를 환경 변수로 로드한다.
  - 소스 URL, Chroma Persistent 저장 경로, 컬렉션 이름을 설정한다.
  - 예시
      SOURCE_URL: 위 한국은행 2025년도 연차보고서 URL
      Chroma 저장 경로: chroma_bok_annual_report
      컬렉션 이름: bok_annual_report_2025


[3] Loading — 웹 문서 로드 및 파싱

  WebBaseLoader의 기본 get_text()만 쓰면 내비게이션·검색창·목차 사이드바 등
  잡음이 섞이므로, 본문 영역을 골라내는 커스텀 파싱을 구현한다.

  요구 사항
  (1) requests + BeautifulSoup(또는 동등한 방식)으로 HTML을 가져온다.
  (2) 다음 영역을 구분·추출한다.
      - bd-view: 제목 / 등록일 / 담당부서 메타데이터
      - introduction-area: 총재 인사말(서문)
      - report-area: 본문(Ⅰ~Ⅲ장 + 참고)
  (3) 텍스트 품질을 해치는 요소를 제거한다.
      - script, style, article(차트 등), 각주 번호(sup), tooltip 링크 등
  (4) 이후 HTMLHeaderTextSplitter 입력을 위해 report-area의 HTML 원문을 보존한다.
  (5) 제목·등록일·담당부서·인사말/본문 길이·미리보기를 출력한다.

  품질 확인
  - report-area 하위 h2~h5 헤딩 개수와 순수 텍스트 분량을 출력한다.


[4] Chunking — 전략별 비교 실습

  샘플 텍스트(또는 샘플 HTML)를 대상으로 다음을 비교한다.

  (1) 고정 Chunking — CharacterTextSplitter
  (2) 고정 Chunking(권장) — RecursiveCharacterTextSplitter
      - 예: chunk_size=500, chunk_overlap=80
  (3) 시맨틱 Chunking — SemanticChunker (샘플만)
  (4) 계층적 Chunking — HTMLHeaderTextSplitter(h2~h5) 1차
      + RecursiveCharacterTextSplitter 2차
      - 헤딩 메타데이터 예: chapter / section / subsection / topic
      - 헤딩만 있고 본문이 거의 없는 조각은 제외해도 된다.

  비교 결과와 선택 근거를 요약한다.
  (권장: HTML 헤더 계층적 1차 + Recursive 2차 하이브리드)


[5] Embedding + Vector DB 저장

  - 총재 인사말을 별도 청크(예: chapter="총재 인사말")로 포함한다.
  - 본문에 계층적 HTML 청킹을 적용한다. (예: chunk_size=800, chunk_overlap=100)
  - 각 청크에 source(URL), title 등 메타데이터를 저장한다.
  - 임베딩 모델: gemini-embedding-2 (또는 최신 모델, 이후 고정)
  - Vector DB: Chroma DB (로컬 Persistent)
  - 재실행 시 중복을 막기 위해 인덱스 재생성/재사용 옵션을 둔다.
  - 최종 컬렉션 문서(청크) 수를 출력한다.


[6] Retrieval — Retriever 비교

  동일 테스트 질문으로 다음 Retriever의 검색 결과를 비교한다.

  (1) Similarity Retriever (예: k=6)
  (2) MMR Retriever (예: k=6, fetch_k=30, lambda_mult=0.7)
  (3) MultiQuery Retriever

  테스트 질문 예시
    "2025년 기준금리는 몇 차례, 총 몇 bp 인하되었나요?"

  상위 청크는 page 번호 대신 헤딩 경로(장 > 절 > 항 > 소제목)를 출력하고
  중복·다양성·관련성 차이를 짧게 해석한다.


[7] Generation — 웹 문서 Q&A RAG 체인

  - grounded 프롬프트를 사용한다.
      · 검색된 문서 내용만 근거로 답변
      · 없는 내용은 추측하지 않음
      · 수치(성장률, 인하폭 등)는 원문 표현 유지
      · 가능하면 출처의 장/절(헤딩 경로)을 함께 언급
  - 역할 설정 예: 한국은행 2025년도 연차보고서 분석 전문가
  - 기본 Retriever는 MMR을 권장한다.
    (인사말·본문 여러 장에 통화정책 등 주제가 반복되므로 다양성 확보)
  - 생성 모델 예시: gpt-4o-mini
  - ask(question) 헬퍼로 질문/답변/참고 청크(헤딩 경로)를 출력한다.


[8] Q&A 동작 테스트

  최소 아래 질문에 대해 답변과 출처(헤딩 경로)를 실행·확인한다.

  1) 2025년 국내 경제성장률과 소비자물가상승률은 어떻게 되나요?
  2) 기준금리는 2025년 중 몇 차례, 총 몇 bp 인하되었나요?
  3) 한국은행 AI 플랫폼 BOKI는 무엇이고 왜 구축했나요?
  4) 프로젝트 한강 파일럿의 내용은 무엇인가요?
  5) 한국은행이 SEACEN 의장국으로서 수행한 역할은 무엇인가요?
  6) (옵션) MultiQuery로 "환율 변동성에 한국은행은 어떻게 대응했나요?" 등 모호한 질문 테스트
  7) (옵션) 자유 질문 1개 이상
      예: 화폐박물관 방문객 수와 관련 활동은 어땠나요?


[9] 정리

  Loading / Chunking / Embedding / Vector DB / Retriever / Generation에 대해
  본 실습에서 선택한 기술과 이유를 표로 정리한다.
