[실습과제] 금융데이터 가이드북 PDF 문서 기반 Q&A RAG 구현

교과목: RAG 파이프라인 설계와 구현
권장 파일명: RAG_파이프라인_설계와_구현_금융데이터_가이드북_QA.ipynb

1. 제공 자료
────────────────────────────────────────

데이터 파일 (실습용)
  - 금융데이터 가이드북 100문 100답(한국신용정보원)_fn+ - 12 Page.pdf
    (한국신용정보원, 12페이지 발췌본)

원본 PDF 다운로드 (한국신용정보원)
  https://www.kcredit.or.kr:1441/archive/financialDataGuidebookView.do
  (금융데이터 가이드북 100문 100답)

※ 실습 주의
  - 원본 PDF는 약 225페이지이며, 전 페이지를 GPT Vision OCR로 처리하면 비용이 크다.
  - 반드시 12페이지 발췌본(…_fn+ - 12 Page.pdf)을 인덱싱에 사용한다.
  - 노트북과 동일 폴더(또는 지정 경로)에 PDF를 두고 경로를 설정한다.


────────────────────────────────────────
2. 과제 목표
────────────────────────────────────────

금융데이터 가이드북(한국신용정보원) PDF를 대상으로
로딩 → (필요 시 OCR) → 청킹 → 임베딩 → Vector DB 저장 → 검색 → 생성까지
완전한 RAG Q&A 파이프라인을 구현한다.

학습 포인트
  1) RAG 전체 아키텍처(인덱싱 파이프라인 / 질의 파이프라인)를 이해한다.
  2) 텍스트 추출이 깨지는 PDF에서 원인을 파악하고 Vision OCR로 복구하는 방법을 익힌다.
  3) Chunking 전략(고정 / 시맨틱 / 계층적)을 비교하고 가이드북 문서에 적합한 방식을 선택한다.
  4) Vector DB(Chroma / Pinecone / Weaviate) 선택 기준을 정리하고, 본 실습에서는 Chroma를 사용한다.
  5) Retriever(Similarity / MMR / MultiQuery)를 비교하고 grounded Q&A 체인을 구성한다.


────────────────────────────────────────
3. 과제 내용
────────────────────────────────────────

[1] 이론 정리 (노트북 Markdown으로 작성)

  다음 내용을 표 또는 요약으로 정리한다.

  (1) RAG 전체 아키텍처
      - 인덱싱: Loading → Chunking → Embedding → Vector DB
      - 질의: Embedding → Retrieval → Generation

  (2) Chunking 전략 비교
      - 고정(Fixed) / 시맨틱(Semantic) / 계층적(Hierarchical)
      - 분할 기준, 난이도, 검색 정확도, 속도, 문맥 유지, 추천 문서 유형

  (3) Vector DB 선택 기준
      - Chroma / Pinecone / Weaviate
      - 배포 형태, 비용, 규모, 하이브리드 검색, 추천 상황

  (4) Retriever 종류 및 성능 특성
      - Similarity / MMR / MultiQuery / Contextual Compression
      - 동작, 장점, 단점, 적합 상황


[2] 환경 설정

  - Gemini API Key를 환경 변수로 로드한다.
  - PDF 경로, Chroma Persistent 저장 경로, 컬렉션 이름을 설정한다.
  - 예시
      PDF: 금융데이터 가이드북 100문 100답(한국신용정보원)_fn+ - 12 Page.pdf
      Chroma 저장 경로: chroma_finance_qa
      컬렉션 이름: finance_guidebook_100qa


[3] Loading — PDF 문서 로드 및 OCR

  (1) PyPDFLoader로 먼저 로드해 텍스트 추출 상태를 확인한다.
      - 총 페이지 수, 일부 페이지 미리보기(repr 등)를 출력한다.

  (2) 추출 실패 원인과 해결을 Markdown으로 정리한다.
      - 본 PDF는 ToUnicode CMap(CID→유니코드 매핑) 손상으로
        화면 렌더링은 정상이나 텍스트 레이어 추출 시 한글이 깨질 수 있다.
      - PyMuPDF 등으로도 동일하면 로더 문제가 아니라 PDF 폰트 인코딩 문제임을 확인한다.

  (3) 페이지를 이미지로 렌더링한 뒤 GPT-4o Vision OCR로 텍스트를 복구한다.
      - 페이지별 전사 결과를 ocr_cache/ 등에 캐시하여 재실행 시 비용·시간을 줄인다.
      - 제공된 pdf_vision_ocr.py 등을 사용해도 되고, 동등한 Vision OCR 로더를 직접 구현해도 된다.
      - OCR 후 정상 한글 미리보기와 메타데이터(page 등)를 출력한다.


[4] Chunking — 전략별 비교 실습

  앞부분 샘플 페이지를 대상으로 다음을 비교한다.
  (전체 PDF에 시맨틱 청킹을 적용하면 임베딩 비용이 크므로 샘플 비교 후,
   실제 인덱싱 전략을 선택한다.)

  (1) 고정 Chunking — CharacterTextSplitter
  (2) 고정 Chunking(권장) — RecursiveCharacterTextSplitter
      - 예: chunk_size=800, chunk_overlap=120
  (3) 시맨틱 Chunking — SemanticChunker (샘플 일부만)
  (4) 계층적 Chunking — 페이지(상위) → Recursive 분할(하위)
      - 하위 청크에 parent_page 등 메타데이터를 유지한다.

  비교 결과(청크 수, 절단 양상, 메타데이터)를 요약하고,
  전체 인덱싱에 사용할 전략을 선택·근거를 적는다.
  (권장: 계층적 1차(페이지) + Recursive 2차 하이브리드)


[5] Embedding + Vector DB 저장

  - 선택한 Chunking으로 전체(12페이지 OCR 결과)를 청킹한다.
  - 임베딩 모델: gemini-embedding-2 (또는 최신 모델, 이후 고정)
  - Vector DB: Chroma DB (로컬 Persistent)
  - 재실행 시 중복을 막기 위해 인덱스 재생성/재사용 옵션을 둔다.
  - 배치 저장(예: 100개 단위)을 권장한다.
  - 최종 컬렉션 문서(청크) 수를 출력한다.


[6] Retrieval — Retriever 비교

  동일 테스트 질문으로 다음 Retriever의 검색 결과를 비교한다.

  (1) Similarity Retriever (예: k=6)
  (2) MMR Retriever (예: k=6, fetch_k=30, lambda_mult=0.7)
  (3) MultiQuery Retriever (LLM 기반 질문 재작성 후 검색)

  테스트 질문 예시
    "신용정보는 무엇인가요?"

  각 Retriever별 상위 청크의 page, 내용 미리보기를 출력하고
  중복·다양성·관련성 차이를 짧게 해석한다.


[7] Generation — PDF Q&A RAG 체인

  - grounded 프롬프트를 사용한다.
      · 검색된 문서 내용만 근거로 답변
      · 없는 내용은 추측하지 않음
      · 가능하면 출처 페이지를 함께 언급
  - 역할 설정 예: 한국신용정보원 '금융데이터 가이드북 100문 100답' 전문 상담원
  - 기본 Retriever는 MMR을 권장한다.
  - 생성 모델 예시: gpt-4o-mini
  - ask(question) 형태의 헬퍼로 질문/답변/참고 청크를 출력한다.


[8] Q&A 동작 테스트

  최소 아래 질문에 대해 답변과 출처 페이지를 실행·확인한다.

  1) 신용정보는 무엇인가요?
  2) 개인신용정보는 어떻게 보호되나요?
  3) 금융데이터는 어떤 목적으로 활용할 수 있나요?
  4) 가상자산거래소가 보유하고 있는 거래정보도 신용정보에 해당하나요?
  5) 금융회사가 고객의 개인정보를 합성데이터로 만들어 활용하는 경우 별도 동의가 필요한가요?
  6) 마이데이터 사업자는 미성년자에게 서비스를 제공할 때 법정대리인의 동의를 확인해야 하나요?
  7) 개인신용정보가 누설된 경우 금융회사는 어떻게 대응해야 하나요?
  8) 금융회사간 영업양도나 합병이 있을 경우 고객 동의 없이 신용정보를 이전할 수 있나요?
  9) (옵션) MultiQuery로 "CB사는 어떤 역할을 하나요?" 등 모호·약어 질문 테스트
  10) (옵션) 자유 질문 1개 이상
       예: 마이데이터란 무엇인가요?


[9] 정리

  Loading(OCR 포함) / Chunking / Embedding / Vector DB / Retriever / Generation에 대해
  본 실습에서 선택한 기술과 이유를 표로 정리한다.
